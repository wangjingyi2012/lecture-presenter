# 中心执行者桥接图

来源页面：`MCP协议/slide05.html`

当前状态：第一版抽象预览，已补齐槽位驱动、分步动效和静态验收规则，先用于确认结构是否值得进入 LectureAI 服务端模板库。

## 模板分类

- 版式族：`concept-bridge`
- 内容类型：系统边界、架构解释、Agent、中间层、概念澄清
- 核心叙事：两端角色先建立关系，中间执行者出现，再揭示执行者的多个实现
- 默认动效：`progressive-reveal`

## 为什么适合模板化

这张页面的可复用价值不在 Agent 或 DeepSeek 品牌，而在稳定的认知顺序：

1. 先看见调用关系的两端；
2. 中间层出现，解释“谁负责真正执行”；
3. 中间层展开为多个实现，完成从抽象到实例的落地。

## 不应模板化的部分

- 特定课程的品牌 Logo；
- 原页面的具体 Agent 名称和解释性弹窗；
- 固定的 4 个实现数量；
- 只适用于本页的坐标和文字长度。

## 使用限制

- 桥接实现最多 4 个，超过应拆页；
- 左右两端必须是明确角色，不能塞入长段落；
- 中间桥接层必须能用一句话解释职责；
- 动效是讲解节奏，不是自动播放；
- 最后一步必须允许宿主演示器翻到下一页。

## 预览

直接打开同目录的 `slide.html`。预览数据位于页面内的 `template-data` JSON，服务端接入时由渲染器替换该数据，不需要把模板规则下发到客户端。桥接项为 1、2、3、4 个时，内部步骤会自动收敛到实际需要的 1、2、3 步。

## 验收文件

`validation.json` 记录模板结构、动效和内容密度的静态约束；它是服务端模板注册前的检查输入，不是客户端运行时配置。
