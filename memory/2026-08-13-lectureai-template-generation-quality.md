# LectureAI 模板生成质量排障报告

日期：2026-08-13

## 测试样本

- 课件：`/Users/jingyi.wang/Documents/workspace/演讲宝使用视频/AI发展史`
- 用户目标：20 页 AI 发展史课件
- 实际结果：21 页、5 个章节过渡页

## 根因

1. 规划只校验 `targetSlideCount == slides.length`，没有校验用户原始页数，也没有章节预算。模型把五页角色母版错误理解为额外页面，形成 21 页和 5 章。
2. 目录、封面、章节、结束页允许自由写完整 HTML。目录内联 CSS 覆盖 `catalog.css`；结束页背景图已有文字，但模型仍写入正文。
3. 服务端私有模板是自包含白底页面，没有继承项目 `content.css`，所以丢失 `AH-CommonPageTemplateBG.png` 等 PPTE 母版视觉。
4. `table-reference-catalog` 与 `table-comparison-matrix` 的标题在模板根节点之外，脚本使用 `root.querySelector`，导致 payload 标题没有替换示例标题。
5. 表格契约允许列数与行数据不一致，模板用破折号静默补列，形成无有效内容的“典型问题”列。
6. 双对象对比只有底线和浅色标题，缺少明确的左右边界；编号要点只有底边，不具备卡片轮廓。
7. 多个模板把正文、解释和流程节点压到 1.4-1.7vw，投影距离下不可读。
8. 整套校验只比较抽象布局，没有核对计划 `templateId` 与页面 `data-template`，模板漂移只能产生弱提示。

## 修复

- 桌面与 Web 工作台增加用户目标页数门禁。用户要求 20 页时，21 页规划会在写盘前被拒绝。
- 服务端规划器增加章节过渡页预算：12 页以内最多 2 个，13-24 页最多 3 个，25-39 页最多 4 个，40 页以上最多 5 个。
- 封面、目录、章节、结束页改为角色母版保护：必须保留原 stylesheet，禁止内联样式覆盖；结束页默认必须保持可见正文为空。
- 私有模板渲染器增加经过项目资源清单核验的 `host_stylesheets`，桌面默认传入根目录 `content.css`；Web 项目渲染自动继承存在的 `content.css`。
- 表格模板修正标题查询作用域，增加严格行列数量校验，并在标题下剩余区域垂直居中。
- 重做 `two-object-comparison` 的左右面板和逐项对照行；为 `numbered-key-points` 增加完整边框、浅底和轻阴影。
- 提升表格、对比、卡片、概念、案例、段落、流程和终端模板中的正文/解释字号；1.5vw 仅保留给标签、步骤按钮等辅助信息。
- 整套校验增加 `templateId` 与实际 `data-template` 一致性检查。
- 私有服务端模板与公开 `模板制作/` 副本同步。

## 2026-08-13 分章规划规则补充

- 默认规则改为：30 页及以内采用连续叙事，不生成目录页和章节过渡页；超过 30 页默认恰好 2 章，最多 1 个目录页和 2 个章节过渡页，每章至少约 15 页。
- 用户明确要求分章、目录或章节过渡时通过 `sectionPolicy` 覆盖默认规则；用户明确要求“不分章”时使用 `mode: continuous`，即使超过 30 页也不强制插入章节。
- 桌面端、Web 工作台和服务端都执行同一门禁。旧规划没有 `sectionPolicy` 时保持兼容，不会被历史数据突然判无效。
- 新建 PPTE 的 catalog/chapter 仅是母版占位页。只有有效整套规划把对应页角色改为 `content` 时，才允许 `write_slide` 或 `render_template replace` 转为正文；cover/finish 永远不能转为正文。

验证：Web 后端全量 `58 passed`；桌面工作台 `npm run test:workbench` 通过；Rust `cargo check` 与 `cargo test` 通过（37 通过、2 个需云凭证的 live caption 测试跳过）。

## 2026-08-13 重复度、教学叙事与字体一致性补充

### 新样本结论

- 重新生成的样本仍为 21 页；19 个正文页使用了 11 种模板，但 `concept-story-progression` 单一模板出现 6 次，占 31.6%。问题不只是模板总数不足，也包括模板选择没有整套分布约束。
- `slide10`、`slide11`、`slide12` 的规划只有各页独立的 `visualIntent`，没有“上一页得到什么结论、本页解决什么认知问题、下一页为何自然出现”的跨页契约，因此单页主题相关但教学推进关系不成立。
- 模板库正文曾混用 1.25-1.75vw 字号及 `#64748b` 弱灰色；即使单页排版没有溢出，投影时也会产生字体偏小、同一课件深浅不一的问题。

### 新增约束

- 新规划统一写入 `qualityPolicy.schemaVersion = 2`。每个正文页必须提供 `narrative.buildsOn/learningGoal/keyTakeaway/leadsTo`，并要求前一正文页的 `leadsTo` 与后一正文页的 `buildsOn` 完全一致。
- 规划阶段必须确定 `templateId/templateVersion`。只有模板库确实无法表达的特殊页面，才允许使用 `renderMode: custom`，并必须提供 `customLayoutReason`。
- 任一模板最多占正文页 25%；同一模板不能在连续三个正文页窗口内再次出现。整套校验新增 `templateKinds` 和 `maxTemplateShare` 指标。
- 私有模板从 17 种增加到 20 种，新增 `history-timeline-ribbon`、`causal-turning-point`、`evolution-stage-ladder`，分别服务于历史里程碑、因果转折和能力逐级演进。
- 全部私有模板统一投影字体规则：正文和解释文字不低于 1.8vw，1.5vw 仅用于短标签；弱化正文色从 `#64748b` 收紧为 `#334155`。交互状态只通过边框、背景、节点颜色和轻微位移表达，不降低整块文字透明度。
- 旧规划未声明 `qualityPolicy.schemaVersion = 2` 时保持兼容，避免历史课件因新门禁突然不可编辑。

### 验证

- Web 后端全量：`62 passed`。
- 桌面工作台：`npm run test:workbench` 通过；`node --check src/js/workbench-window.js` 通过。
- Rust：`cargo check` 与 `cargo test` 通过（37 通过、2 个需云凭证的 live caption 测试跳过）。

## 2026-08-13 长课件分页 Harness

### 架构调整

- 整套生成不再使用一个持续膨胀的模型会话。客户端先进行一次 `deck-plan` 规划，保存权威 Deck Plan；规划通过后进入分页 Harness。
- 每页 Worker 都从新的两条消息开始：单页系统规则 + 动态页面上下文。当前页完成后销毁该消息数组，不把上一页 HTML、工具调用或校验回执带到下一页。
- 单页动态上下文仅包含：用户原始目标、全局视觉规范、全套精简页序、当前页前后各两页详细规划、相邻已完成页摘要、最近阶段审查建议、当前页固定写入指令。
- 每页只允许操作规划指定页，必须使用规划指定模板、写入模式和插入位置；写入后必须通过 `validate_slide`。客户端拒绝越页、换模板、擅自重排和重复插入。
- 服务端聊天接口新增 `context_mode`：`deck-plan` 使用完整课件 Skill；`page-worker` 只注入单页规则和当前页指定模板的私有契约；`stage-review` 不加载模板目录。

### 连贯性与恢复

- 每完成 5 页，客户端使用页面摘要和后续三页规划执行一次阶段审查，检查教学递进、概念跳跃、术语漂移和模板节奏；审查建议进入后续页面上下文。
- 执行状态写入 `.lectureai/deck-plan.json` 的 `execution` 字段：`completedPages`、`summaries`、`stageReviews`、`nextPage`、`status` 和原始用户目标。摘要不包含 HTML。
- 停止按钮会中断当前模型请求并阻止下一页启动；输入“继续”“继续生成课件”可从已保存游标恢复，已完成页面不会重跑。
- 整套校验失败后最多执行两轮定向返工：优先从错误中提取具体页码，只重新生成相关页面；全局动画或布局问题选择少量正文候选页，不重跑整套。
- 桌面五页母版由 Harness 负责按规划转换或克隆角色页；单页 Worker 不负责页序和母版调度。Web 从单封面项目按规划固定插入位置逐页扩展。

### 测试覆盖

- 多页模拟明确验证：第一页会话从 2 条增长到 6 条后，第二页重新从 2 条开始，且第二页不包含第一页工具回执。
- 纯函数测试覆盖前后两页窗口、无 HTML 上下文、模板漂移拒绝、越页拒绝、恢复指令识别和当前模板目录裁剪。
